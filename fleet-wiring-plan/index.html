Fleet wiring plan: Grok Bot as a peer in _Handoffs + Paperclip

Bottom line

Half the bridge already exists.

Paperclip can already push work to every Grok Bot bot: 30 Grok agents are registered in Paperclip with an http adapter that calls a Grok Bot webhook routine. What is missing is the way back. Paperclip and _Handoffs live on the Mac Studio's localhost and external drive, and Grok Bot bots run on a cloud box that cannot reach either. Build one narrow, token-protected return gateway on the Mac, unpause the Grok agents, and make every unit of work a DIG issue. Then Grok Bot is a peer like everyone else.

Volume is not capped by skills or by usage. It is capped by work that never reaches the bot that should do it, and by results that never come back. The steps below fix that in order.

One loop, three layers, no duplicates

PaperclipSource of truth: owner, status, DIG id
_HandoffsPayloads: scripts, films, receipts
AgentBusWake and notify only
Mac seatsARA, ECHO, ROGUE, CHIEF, KEYSTONE, Codex, Mason
Fleet gatewayNew, narrow, token per bot
Grok Bot fleetT06, O03, SP-02 and the rest
  • Mac seats → Paperclip: local API
  • Mac seats → _Handoffs: atomic write
  • Paperclip → Grok Bot fleet: assignment webhook (exists)
  • Grok Bot fleet → Fleet gateway: HTTPS via Funnel
  • Fleet gateway → Paperclip: comment, status
  • Fleet gateway → _Handoffs: read and write payloads
  • Fleet gateway → AgentBus: pointer message (optional)
LayerJobRule
PaperclipWho owns what, and whether it is doneEvery unit of work is a DIG issue. No issue, no work. Status changes happen here, nowhere else.
_HandoffsWhere the actual files liveEvery deliverable goes into `<DIG###>/` with a SHA sidecar. The issue comment links the path.
AgentBusWake a seat, tell a humanA bus message carries a DIG id and a path, never the work itself and never a status. Keep it for seats without a Paperclip adapter and for the Slack mirror.

This keeps AgentBus as the original wake layer and Paperclip as the board above it, as ARA described, and stops the two from competing for status. The 131,651 unread messages in ARA's seat show what happens when the bus carries work: nobody can consume it.

Outbound: how a Grok Bot bot hands work back

Build a small HTTP service on the Mac Studio, bound to 127.0.0.1, published as one more Funnel path next to the existing ones. It talks to Paperclip locally, so Paperclip itself stays private. Each Grok Bot bot gets its own token, saved as a secret in that bot.

Why not expose Paperclip directly

In `local_trusted` mode a request with no token is the board owner. Putting port 3100 on Funnel would give the whole internet full board access. Paperclip's own docs say to switch to `authenticated` mode before any network exposure, and its public MCP endpoint needs HTTPS plus real user accounts with OAuth. That is the right long-term path, but it changes how every Mac seat logs in, so do it second.

Why not the registered-Mac shell

Grok Bot bots can run commands on the Mac Studio as a registered machine, and that is how bots sent AgentBus replies in October. Each call can need an approval, the Mac mini and M2 Studio are offline to Grok Bot, and it is not unattended. Keep it as a break-glass path, not the bus.

Take ARA out of the review loop

CH20R3 sat since Nov 1 because no agent applied the fix. It only needed its end trimmed. QA is now agent-only: agents use Argon 4 to watch the video and send edit instructions to the video's owner, and the video agent can run that analysis itself in Argon 4 in the browser or the Gemini/Antigravity app. A trimmed silent ending is a pass. First action: trim CH20R3 from 66.49s onward, re-run QA, and publish. No human review.

  1. Audio present for the full runtime; no silent tail longer than 1 second (the CH20R3 failure). Trim it, and it passes.
  2. Script match: every on-screen line and voice line matches Mason's approved words exactly.
  3. Spec: aspect ratio, length window, captions burned in, no watermark, no broken frames.
  4. Brand and compliance: banned claims list for each offer, product names spelled right.
  5. Two rejections on the same film go back to the video agent with the Argon 4 notes. The agent fixes and resubmits. No human review.

Skill sync from 00_SKILLS_CANONICAL

  1. Treat 00_SKILLS_CANONICAL as the only source

    325 top-level entries and 477 MB on the drive (ARA counts 438 SKILL.md files). Ignore Desktop/T2B_SKILLS_CANONICAL. The `_PACKAGED_GROK_CLAUDE` folder inside is from Aug 17, older than the Oct 4 canonical, so do not install from it.

  2. Give each Grok Bot bot an allowlist

    T06 gets video and QA skills, the media-buying desk gets ad skills, and so on. Loading all of them into every bot wastes usage and confuses routing.

  3. Serve a read-only bundle through the gateway

    A nightly job zips the allowlisted skills; the Grok Bot Orchestrator pulls the bundle and updates each bot's skills, skipping any skill whose hash did not change.

  4. Log what changed

    One line per changed skill on the daily count message, so drift is visible.
